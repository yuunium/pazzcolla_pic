# ぱずこら 覚醒画像

iOS・Android共通の覚醒画像と一覧です。アプリは起動時・バックグラウンドから戻ったときに `catalog.json` を確認します。

## 通常の更新はこの2か所だけ

1. 画像を `images/画像ID.png` にアップロード・上書きします。
2. `catalog.json` を編集し、最後に `version` を前回とは違う文字列に変えて保存（Commit changes）します。

`version` は好きな文字列です。例えば `"2026-11-12-2100"`、`"2026-11-13-1"`、`"update-A"` が使えます。**必ずダブルクォートで囲んでください。** 日付としての計算や大小比較はしません。アプリに保存してある値と違えば更新します。同じ値のままでは画像を上書きしても更新されません。過去に使った値を再利用しないでください。

画像を先にすべてアップロードしてから、最後にJSONの `version` を変更してください。一度にまとめてコミットしても構いません。画像の変更だけなら、JSONは `version` だけ変えれば十分です。

## JSONの書き方

```json
{
  "version": "2026-11-12-2100",
  "groups": [
    {
      "name": "パズル系火力覚醒",
      "images": ["7c", "10c", "10c_p"]
    },
    {
      "name": "補助効果覚醒",
      "images": ["boost", "boost_p"]
    }
  ]
}
```

- `version`：自分で決める更新番号。更新のたびに変えます。
- `groups`：覚醒の分類。一覧に書いた順に表示されます。
- `name`：アプリに表示する分類名。自由に変更できます。分類名は重複させないでください。
- `images`：画像ID。一覧に書いた順に表示されます。拡張子・フォルダ名・URLは不要です。

例えば `"10c_p"` と書けば `images/10c_p.png` が読み込まれます。
画像IDは半角英数字・アンダースコア・ハイフンで1〜100文字、大文字小文字もファイル名と一致させてください。同じIDは一覧全体で1回だけ指定してください。PNG形式（各辺4096px以下、1枚10MB以下）を使います。

### 覚醒を追加する

1. 例えば `images/new_awoken.png` をアップロードします。
2. 対象の `images` に `"new_awoken"` を追記します。
3. `version` を新しい値に変更します。

### 並べ替え・分類変更・非表示

- 並べ替え：`images` または `groups` の順番を変えます。
- 分類追加：`groups` に `name` と `images` の組を追加します。
- 分類変更：画像IDを別の分類へ移動します。
- 非表示：画像IDをJSONから外します。空になった分類は分類ごと削除します。
- どの変更も最後に `version` を変更してください。

**既存画像のIDは変更しないでください。** 保存済みカードと文章中の `[10c]` などのアイコンはIDで対応付けています。非表示にした画像ファイルもリポジトリに残しておくことをおすすめします。取得済みの端末では非表示後も画像を保持するため、過去のカードを表示できます。

JSONではコメント・末尾の余分なカンマを使えません。

## アプリ側の動作

- 起動・画面復帰ごとにJSONを通信で確認します。アプリの画面はその間も操作できます。
- 更新番号が同じ場合、画像のダウンロードは行いません。
- 更新番号が異なる場合、一覧内の画像をすべて取得します。個別のハッシュを管理する必要はありません。
- JSONとすべての画像を検証してから、一覧・画像をまとめて切り替えます。
- JSONの記述ミス、画像の不足、通信失敗があれば前の状態を維持し、次にアプリを開いたとき再試行します。
- 取得した画像はアプリの内部領域に保存し、オフラインでも使えます。
- 初回の通信失敗時にはアプリ同梱の覚醒画像を使います。
- 覚醒の選択一覧と文章入力用の覚醒一覧の両方に反映されます。タイプ画像・ドロップ画像・背景などは今回の配信対象に含みません。

この仕組みに対応したアプリを最初に一度リリースする必要があります。その後の覚醒一覧・画像の変更は、このリポジトリの更新だけで反映できます。

## アップデートのお知らせ

画像配信とは独立して、ルートの `update_notice.json` を編集すると、iOS・Android両方にお知らせを出せます。アプリ本体のバージョンに関係なく全員が対象です。

```json
{
  "version": "2.2.0",
  "message": "新しいバージョンを公開しました。\nストアからアップデートをお願いします。"
}
```

- `version`：見出しと「もう表示しない」の判定に使う通知の番号です。見出しは「バージョン2.2.0のお知らせ」になります。必ず文字列で指定します。
- `message`：通知本文です。改行は `\n` と入力します。
- 入力する項目はこの2つだけです。アプリ用のストアURLをJSONへ書く必要はありません。
- 起動時・画面復帰時に確認します。「閉じる」だけなら次回も表示します。
- 「もう表示しない」にチェックして「閉じる」または「アップデート」を押すと、その `version` は今後表示しません。
- 次のお知らせで `version` を変えると、以前チェックした人にも新しい通知を表示します。同じ番号で本文だけ変えても、非表示にした人には出ません。
- 「アップデート」はiOSならApp Store、AndroidならGoogle Playを開きます。
- アプリの編集内容を「全て初期化」しても、この非表示設定は保持します。
- JSONの読み込みに失敗してもアプリは通常どおり使えます。

### お知らせを止める

```json
{
  "version": "",
  "message": ""
}
```

どちらかが空欄なら通知しません。初期状態はこの停止状態です。実際にストアへ更新を公開したときに、通知内容を入力してください。

GitHubの配信キャッシュにより、変更が届くまで数分かかる場合があります。この通知機能を組み込んだアプリを最初に一度リリースする必要があります。
